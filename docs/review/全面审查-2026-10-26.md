## 1. 解析层(P)

### P1 · 高 · 带内容的 `$$` 公式吞掉后续正文
- **位置**:`lib/markdown/parser.ts` `matchMathOpen`(155-166)、主循环多行公式分支(484-509)。
- **输入**:`$$ a+b\n$$\n\n正文段落\n\n$$\nc\n$$`
- **实际**:`unstyled "$$ a+b"`、`LATEX "正文段落"`、`unstyled "c"`、`unstyled "$$"`。
- **期望**:正文段落保持段落,`c` 成公式。
- 同类:`$$\nE=mc^2 $$\n\n正文\n\n$$\ny\n$$` → LATEX 成了 `E=mc^2 $$\n\n正文`。
- **根因**:起行带内容(`$$ a+b`)或闭合行带内容(`E=mc^2 $$`)都不被识别;剩下的裸 `$$` 行向下无界搜索闭合行,跨空行、跨段落与下一段公式的起行配对。
- **影响**:正文静默变成一个渲染失败的公式块,能力面板还报「数学公式 1 · 原生」。Obsidian / MathJax 均接受这种写法。

### P2 · 中 · 未闭合围栏后的代码被当 Markdown 解析
- **位置**:`parser.ts:447-468`、`frontmatter.ts:183-203`。
- **输入**:`正文\n\n```python\n# 注释\ndef f(*args, **kw): pass\n- x`
- **实际**:`extractTitle` → `{ title: "注释", source: "h1" }`;`# 注释` 成 header-one、`- x` 成列表项;`h1Handle=remove` 会删掉这行代码。能力面板无「围栏未闭合」提示(未闭合 `$$` 有)。
- **期望**:不从代码里抽标题,并提示围栏未闭合(CommonMark 把文档余下部分视为代码)。

### P3 · 中 · 多行 HTML 注释里的标题成文章标题
- **位置**:`parser.ts:583-608`、`frontmatter.ts:183`。
- **输入**:`<!--\n# TODO: 替换成项目名\n- 说明\n-->\n\n# 真正的标题\n\n正文`
- **实际**:标题「TODO: 替换成项目名」;注释被写成 `<!--`、一个 H1、一个列表项;`stripFirstH1` 删的是注释里那行,真标题留在正文。
- **期望**:跳过注释(或整段作一个文本块),标题为「真正的标题」。README / issue 模板常见。

### P4 · 中 · `stripFirstH1` 整行删除导致上下文重拼
- **位置**:`lib/markdown/frontmatter.ts:216-224`(`lines.splice(start, end - start)`)。
- **输入**(`h1Handle=remove`):`# 标题\n---\n作者:张三\n---\n\n正文`
- **实际**:原文块为 `[H1 标题, DIVIDER, H1 作者:张三(setext), 正文]`;删行后首行变 `---`,被判为 frontmatter,只剩 `[正文]`——分割线与作者行丢失。
- 同类:`导语\n# 标题\n正文` → 合并为一段 `导语\n正文`;`- 要点\n# 标题\n正文` → `正文` 被吸进列表项。
- **期望**:只去掉标题块,其余块不变。

### P5 · 中 · 引用块里的代码被改坏
- **位置**:`parser.ts:611-616`(引用逐行 `walkInline`)。
- **输入**:`` > ```py\n> def f(*args, **kwargs): return a*b*c\n> ``` ``
- **实际**:三个 blockquote 块;中间一行变成 `def f(args, **kwargs): return ab*c` 并带 ITALIC(offset 6,length 25)——代码里两个 `*` 被删。
- **期望**:代码原样保留。
- 相关:`>> 内层` 产出字面量 `> 内层`;GitHub alert `> [!NOTE]` 保留字面量(与 backlog「引用 lazy 续行」不是同一项)。

### P6 · 中低 · 列表项内非列表块后子项层级被重置
- **位置**:`parser.ts:424-432`(上一块不是列表项即清缩进栈)。
- **输入**:`- a\n  ```js\n  x\n  ```\n  - b`、`- a\n  ![](x.png)\n  - b`
- **实际**:`b` 的 depth 为 0;**期望** 1。2 空格缩进即触发,与 backlog P4(4 空格 / Tab / 松散段落)不同。X 目前扁平化列表,主要影响 depth 数据正确性。

### P7 · 中低 · frontmatter 引号标题不解码转义
- **位置**:`frontmatter.ts:28-38`(`stripQuotes`)。
- `title: 'It''s fine'` → `It''s fine`(应为 `It's fine`);`"He said \"hi\""` → `He said \"hi\"`;`"C:\\path"` 保留双反斜杠。这是写进 X 的标题。

### P8 · 中低 · 强调符配对跨进链接目标
- **位置**:`parser.ts:1366-1421`(`findClosing` 跳过代码 span,但不跳过 `](…)`)。
- `**注意 [链接](https://a.com/a**b) 结束**` → 链接丢失,URL 中 `**` 被删。
- `*[Python](https://en.wikipedia.org/wiki/Python_*)*` → 链接丢失。
- `_参见 [文档](https://a.com/my_doc)_` → 斜体丢失,留下字面 `_…_`。
- **期望**(CommonMark):链接优先,外层强调包住链接。

### P9 · 低 · 链接 title 内的 `)` 截断 URL
- **位置**:`parser.ts:1323-1340`(`matchLink`)。
- `[a](https://a.com "title with ) paren")` → 正文 `a paren")`。

### P10 · 低(病态输入)· 未闭合围栏块级 O(n²)
- **位置**:`parser.ts:436-446`、`869`。每个未闭合开栏行都向下扫到文末。
- `'```js\n'.repeat(N)`:30 KB 0.46s、60 KB 1.7s、120 KB 6.4s;`extractTitle` / `stripFirstH1` / 能力面板每次编辑都会重跑。backlog A21 只覆盖行内层。

### P11 · 低 · 能力面板计数与实际写入不一致
- **位置**:`capability.ts:87-96`;`WorkspaceProvider.tsx:546`。
- 行内代码里的 `` `[^1]` ``、`` `![a](b.png)` `` 被计为脚注 / 行内图片;`<!-- 注释 -->` 原样写入却无 HTML 提示;`#### 四级` 同时计为原生加粗与降级标题;导入报告用原始 md 统计,`h1Handle=remove` 删掉的 H1、`coverKeep=remove` 删掉的封面图仍被计入。

### P12 · 低 · 空 ATX 标题
- **位置**:`parser.ts:80`、`689-691`。`#` → 段落 `#`;`# #` → header-one `#`;`#### ####` → 加粗段落 `####`。CommonMark 下应为空标题。

## 2. 侧边栏 / 存储 / 设置(W)

### W1 · 中 · 报告与历史存了过期的解析开关
- **位置**:`WorkspaceProvider.tsx:545`(读 `opts.obsidianImg/wikilink/taskList`)、`:597`(依赖数组缺这三项)。
- **场景**:草稿含 `- [ ] task` 与 `[[wiki]]` → 设置里改任务列表为「纯文本」、关「双链转文本」→ 不改草稿直接写入。正文按新开关解析,`lastRunSnapshot.parseOpts` 与 `history[0].parseOpts` 却是旧值 `{taskList:'symbol', wikilink:true, obsidianImg:true}`。
- **影响**:报告明细、降级数、历史标题按未生效的开关计算,且永久存进历史(正是 B4-6 声称修过的问题)。改稿或切语言会重建回调,所以平时不易发现。

### W2 · 中 · 草稿保存的迟到回声被当外部编辑采纳,丢字
- **位置**:`WorkspaceProvider.tsx:257-276`(`flushDraft` 在写入完成前清空 pending)、`:358-379`(onChanged 采纳判定)。
- **场景**(单窗口):输入「A」→ 250ms 后开始保存 A,写入较慢(如草稿含大 dataURI)→ 输入「B」→ 开始保存「AB」→ A 的 onChanged 到达:`incoming !== mdRef`、无 pending、未在导入 → 采纳,编辑框回退为「A」并 toast「草稿已从另一窗口同步」→ 用户继续输入得「AC」→「AB」的回声因有 pending 被忽略,「B」永久丢失。
- Settings / Prefs 已用「自写回声队列」解决同类问题,草稿没有。

### W3 · 中低 · 新建文章页显示「未在文章编辑页」
- **位置**:`StatusBar.tsx:69`、`PreflightCard.tsx:24-29` 以 `articleId !== null` 判定;新建页 `articleId === null` 但 `useConnection` 判为已连接、写入可用——界面自相矛盾。应改用 `isArticleEditor`。

### W4 · 中低 · 编辑框无法拖放文字
- **位置**:`EditorCard.tsx:86-87`。`onDrop` 无条件 `preventDefault`,从网页拖入文字、框内拖动选中文字都失效。只应在 `dataTransfer.types` 含 `'Files'` 时拦截。

### W5 · 中低 · 重探时横幅闪烁、写入按钮短暂禁用
- **位置**:`useProbe.ts:90`(每轮探测 `setStatus('probing')`)、`DraftTab.tsx:76`。写入后、切标签、甚至**其他窗口**切标签(`onActivated` 未按窗口过滤)都会触发。建议重探期间保留上一次 ready 结果。

### W6 · 低 · 本地封面不显示文件夹入口
- **位置**:`AssetsCard.tsx:178`。`hasLocal` 只看正文图;`cover: ./c.png` 且无本地正文图时不显示「本篇图片文件夹」行,导入才报 `local-no-folder`。

### W7 · 低 · 报告卡标题栏恒为成功样式
- **位置**:`ReportCard.tsx:71-76`。绿色对勾与背景写死,全部失败时也显示;与 Footer 的红色状态矛盾。

### W8 · 低 · 记录上限改小不立即生效
- **位置**:`WorkspaceProvider.tsx:581-585`。只在 `finishImport` 裁剪;改设置、恢复备份都不裁剪,与设置文案「超出后自动清理最旧记录」不符。

### W9 · 低 · 「清除所有数据」不断开本地文件夹
- **位置**:`WorkspaceProvider.tsx:930-955`。只删 4 个 `chrome.storage` key;文件夹 handle 在 x.com 的 IndexedDB,reload 后设置页 / 素材板挂载校准又把「已连接」写回。

## 5. 可优化点(O)

1. **一次导入整篇解析约 4 遍**(`extractTitle`、`stripFirstH1`、`parseMarkdown`、报告 `capability`;`forEachContentLine` 为取钩子也跑完整 `parseLines` 含 `walkInline`),160 KB 文档每遍 35–50 ms。改为单次解析同时返回标题 / 围栏等元数据。
2. **预览改用 `parseMarkdown` 产出渲染**:同时解决预览与写入语义不一致,并可去掉 react-markdown + remark-gfm(侧边栏主包 442 KB);退一步做懒加载。
3. **拆分 WorkspaceProvider 单一 context**:每次按键 / toast / 进度都让所有卡片重渲染。
4. **抽 `useSyncedStorageSlice` 通用 hook**:Settings 与 Prefs 的同步逻辑重复,草稿 / 历史可复用其回声判定(与 W2 修复方向一致)。
5. **`parseMarkdown` 写模块级开关不还原**:统一走 `withParseOptions` 或改为传上下文对象。
6. **能力面板计数由 `walkInline` 解析时上报**,不再对产出文本跑正则(顺带修 P11)。
7. **草稿写失败后的重试**:失败后不重置 max-wait、不安排重试——持续失败时每次按键整篇写一次,停止输入后又不再重试。
8. **死代码**:`stripFirstImageLine` / `isImageLine`(仅测试使用,且 `isImageLine` 不认 `obsidianImg=false`)、`editorHasContent`(context 中无人消费)、`setAccent` / `ACCENTS`、`SettingsTab` 与 `AssetsCard` 重复的 `folderErrText`。
9. **加 `eslint-plugin-react-hooks`(exhaustive-deps)进 CI**:W1 这类依赖遗漏可在提交时拦下。
