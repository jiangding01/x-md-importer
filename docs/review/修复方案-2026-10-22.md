# MarkFlow 发版修复方案 v2（经对抗性复核）— 2026-10-22

## 复核发现并修正的 7 处问题

| # | 原方案的问题 | 修正 |
|---|---|---|
| 1 | 「重生成 lockfile」多余且有风险：本机 registry 是公司 artifactory，重生成可能把私有源写进 lockfile；lockfile 9.0 在 pnpm 11.x 内换版本无需重生成 | 只改 `packageManager` 字段为 `pnpm@11.18.0`，用 `pnpm install --frozen-lockfile` 验证 |
| 2 | B1 的 `commitAndWait` 以「`props.editorState === ns` 恒等」判定提交完成，若 X 的 onChange 对 state 做了包装/派生，恒等永不成立，每步都超时 | 改为**谓词等待**：`settle(node, expect: (content) => boolean, timeout)`，默认谓词为「marker 块文本已变 / MEDIA 已出现」；谓词未定义时退化为固定 `delay(250)`（对齐蓝本）。超时返回 false 并上报，不阻断 |
| 3 | B3 用 articleId 非空做闸门会把新建文章页（无 id）误拒 | 闸门改为 `location.pathname.startsWith('/compose/articles')`（文档与 HANDOFF 确认的 URL 模式），探针回传 `isArticleEditor`，useConnection 的 `connected` 要求它为 true；articleId 仍可为 null |
| 4 | 去掉 `tabs` 权限后，非 X 页面的 `changeInfo.url` 不可见，C29「导航到非 X 域重探」若按 url 触发会失效 | useProbe 改为「活动 tab 的 `status==='complete'` 即重探」，不看 url；探针失败自然落到 disconnected |
| 5 | 隐私政策放 README 锚点：仓库是 PRIVATE，商店审核员打不开 | 写 `docs/privacy-policy.md`（中英双语），**用户需发布到公开地址**（GitHub Gist 或任一公开页面），商店后台填该 URL。这是用户侧前置条件 |
| 6 | 审查分支疑点 1（直写路径权限申请前多了探针 await）没排进任何批次 | 进阶段 1：`writeX` 直写分支先同步解析 blocks 并 `permissions.request`（手势链第一个 await），再探针取 articleId |
| 7 | 阶段 2 的 B2「超时晚到 MEDIA」只写了「FIFO」，无失败兜底 | 定稿：超时图入 `pendingLate` 队列；后续出现的新 MEDIA 先按 FIFO 分配给最早超时图（删 fallback 文本并归位）；循环结束审计 `新增 MEDIA 数 > imageOk` → 上报 `orphan-media`。全程需真机 |

## 前提假设（最脆弱的一条）

**本方案假设 X 的 Draft.js 编辑器内部结构自 7 月真机验证以来没变。** 若 X 已改版，injector 会整体失效，B1/B2 的修复无从验证。缓解：用户现在就用 main 的 build 跑一次最基础的导入（纯文本 + 1 张远程图），作为并行的早期信号；若失败，先转 `/hunt` 排查 X 改版，再继续。
