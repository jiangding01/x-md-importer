## 1. 阶段 1 — 静默错误与 #33 回归

### B1 本地图同名歧义

**现状**:`lib/bridge/localVault.ts:293-316`(`wantsIndexLookup` / `pickFromIndex`)、`:377 resolveLocalFileByIndex`、`:405 resolveAcrossRoots`、`:427-452 resolveFromScopes`。`./x.png`、`../a/x.png`、`x.png` 直读失败后按文件名索引;多候选取段数最少,同长取 BFS 先入(readdir 顺序不定)。导入时只有 md 的 `File`,无路径,无法按 md 所在目录解析。

**修法**:
- `pickFromIndex` 返回 `{ segs } | 'ambiguous' | null`:
  - 原始路径以 `./` / `../` 开头:候选 > 1 → `'ambiguous'`。
  - 单段文件名(Obsidian 短链接语义,Obsidian 仅在文件名唯一时写短链):取段数最少者;最少段数并列 > 1 → `'ambiguous'`。
- **作用域优先级**:按现有 roots 顺序(active 先于 persistent)逐个作用域查,**第一个有候选的作用域决定结果**——唯一 → 命中;歧义 → 返回 ambiguous,**不再往后找**(避免跳到默认文件夹拿到别的图)。
- 解码两遍(decoded / raw):任一遍唯一命中即用;否则只要一遍歧义 → ambiguous。
- `LocalResolveResult` 增 `{ reason: 'ambiguous' }`;`entrypoints/content.ts:128-135` 映射为新原因码 `local-ambiguous`;`lib/bridge/protocol.ts` 的 `ImageFailReason` 增该码;`ReportCard.tsx:12` 的 `Record<ImageFailReason,…>` 增映射(漏写 tsc 会报错);`lib/i18n/dict.ts` 中英新增 `rsnLocalAmbiguous`:
  - 中:「文件夹内有多张同名图片,无法确定是哪一张。请改用相对文件夹根目录的完整路径,或把本篇所在文件夹设为本篇图片文件夹。」
  - 英:「Multiple images with this name exist in the folder, so the right one can't be determined. Use the full path from the folder root, or set this post's own folder as its image folder.」
- 注释同步:`localVault.ts:299-302`、`:347`、`:420-426`。
- 存储与 resultGuards 无原因码白名单(reason 为任意字符串),无需改。

**测试**(`localVault.test.ts`,沿用 fake FS):
- 改写 `pickFromIndex` 现有用例(`:402-412`)适配新返回形状。
- 新增:Hugo bundle `posts/a/cover.png` + `posts/b/cover.png` 导入 `./cover.png` → ambiguous;`img.png` 两处同深度 → ambiguous;两处不同深度 → 取浅者;唯一 → 命中;`../assets/a.png` 两处 `…/assets/a.png` → ambiguous;active 歧义 + persistent 唯一 → ambiguous(不落到 persistent);active 无候选 + persistent 唯一 → 命中。

### B2 超时晚到 MEDIA 归属

**现状**:`entrypoints/injector.ts:505-760`、`:1012-1015`、`:1432`、`:1475`、`:1491`、`:1557-1570`。图 k 超时且 `pendingKey` 为空或之后消失时,k 的晚到块首次以 ready 出现会被图 k+1 当成自己的;末轮 FIFO 把任意无主 ready 块分给最早超时项,无归属证据、猜错即两图对调且全报成功。

**修法**(不猜归属,如实上报):
1. **删除末轮 FIFO**:`recoverLateOnce` 去掉 `allowFifo` 参数与分支;保留循环中及循环结束后(`:1475`)的**精确** pendingKey 扫描。删掉只写不读的 `claimedMedia` / `ownPending` 相关代码(`:533`、`:705`、`:1013`、`:1432` 一带,以实现时 rg 结果为准,确认无读取点再删)。
2. **收尾时一条不确定提示**:在 `imageFail` 取值(`:1491`)之后、与孤儿审计同处:当 `orphanMedia > 0`,且 `pendingLate` 中存在「不可追踪」项 k(`pendingKey` 为空,或其 key 已不在当前 blockMap)、且 k 之后有成功归位的图时,push **一条** `media-order-uncertain`(index = 最早的不可追踪 k,stage `upload`,detail「第 k+1~n 张图位置可能错位」),不计 imageFail。
   - 取舍:以 `orphanMedia > 0` 为门槛压误报(X 拒收某图时全程无 pending 块是常态,不能每次都报错位);代价是「错位链最后一块在审计之后才到」时漏报——此时孤儿也不可见,属已知残留,写入 backlog。
3. 注释同步:`:505-509`、`:515-517`、`:629-636`、`:692-694`、`:1012`、`:1472-1474`。
- 原因码同 B1 的接线(protocol / ReportCard / dict `rsnMediaOrderUncertain`):
  - 中:「此前有图片上传超时且其结果晚到,这张及之后的图片位置可能错位,请在 X 编辑器中核对。」
  - 英:「An earlier image upload timed out and arrived late; this and later images may be out of place. Please check them in the X editor.」

**验证**:injector 不在 vitest 范围;静态复读 + 真机 T17(QA 文档改写:不再期待「被末轮追回」,改为「无静默错位;出现错位时报告带不确定提示」)。

### B4 权限被拒的计数与归因

**现状**:`lib/workspace/WorkspaceProvider.tsx:669-683`(toast 按全部远程图计数)、`:771-779`(权限被拒期间所有 `Failed to fetch` 改标);`permissions.request` 全有或全无,已授权 origin 不受影响;对方 `ACAO:*` 时无权限也能下载。

**修法**:
- `lib/bridge/imagePermissions.ts`:
  - 导出 `originPatternOf(src): string | null`(`${origin}/*`,解析失败 / 非 http(s) / 被拦主机 → null),`addRemote` 与下列纯函数共用,不再有第二套 origin 计算。
  - `requestRemoteImagePermissions` 返回 `{ granted, origins, deniedOrigins }`:**request 仍是第一个 await**;request 返回 true → `deniedOrigins = []`,不调 contains;返回 false 或抛错 → 之后逐 origin `permissions.contains` 求未授权集合;contains 也抛错 → `deniedOrigins = origins`。

**测试**(`imagePermissions.test.ts`):request=true → 不调 contains、`deniedOrigins=[]`;request=false + contains 部分 true → deniedOrigins 正确;request 抛错 + contains 抛错 → 全部;现有 `toEqual({granted:true, origins:[]})` 断言补 `deniedOrigins`;两个纯函数各覆盖已授权 / 被拒 / 截断 source / 封面。

## 2. 阶段 2 — 解析器性能与旧问题

### P1 + P2 findClosing 记忆化(行为零差异)

**不采用**「预计算行内代码区间表」:与现有 walker 不等价(未配对长反引号串从中间重扫、链接目标与 wikilink 先于代码被吃掉),会改变行为。

**修法**(评审原型已验证):
- `findClosing` 从任一起点出发的扫描路径确定,结果是起点的纯函数。每次 `walkInline` 调用内,按定界符各建 `Int32Array` 记忆表,扫描路径上的位置统一回填结果;删除 `noCloseFrom`。
- 同字符定界符串:walker 判定整串不能开时整串按字面输出并跳过,按位置缓存串尾避免重复计算 canOpen;`findClosing` 多字符分支 canClose 失败跳过整串;单字符分支同样按串记忆化(覆盖「能开」的长串 `'*'.repeat(20000)+'a'`)。注意:不能把串内所有位置都填成起点的结果——串内末位剩余长度为 1,若其 canClose 成立它本身就是闭符,须按位置分别判定。

**验收**:
- 差分模糊对比 `0ec9b15` 解析器:字母表 `* _ ~ \` \\ [ ] ( ) ! 中 空格 a \n ** `` ~~`,长度 ≤30 共 60 万例 + 长度 ≤120 共 15 万例,wikilink / obsidianImg 开关各组合,**零差异**。脚本放 `lib/markdown/` 外(scratchpad),不进仓库。
- 性能用例(parser.test.ts):`'**x \`y\` '.repeat(8000)`、`'调用 *args 与 \`f()\` 。'.repeat(8000)`、`'a'+'~'.repeat(50000)`、`'*'.repeat(20000)+'a'`;先用小输入预热一次,再取 3 次最小值,阈值 300ms(改前实测均 >1.5s,改后 <50ms,两侧留 5 倍以上余量)。这些用例在 `0ec9b15` 上应为红。
- 现有用例全绿。

### P5 续行里的有序列表

`absorbListContinuation`(约 `:345`):
- `RE_UL` 或 `1.` 起始(`RE_OL_INTERRUPT`)的行 → 一律 break(现状)。
- 序号非 1 的有序行:缩进 < 当前项内容列 → break;缩进 ≥ 当前项内容列 → 作为续行吸收(CM:不能打断段落)。**不看当前项是有序还是无序。**
- 未缩进的 `- 去年\n2024. 冬天很冷` 保持现状(与 commonmark.js 一致:`<ul>` 后接 `<ol start=2024>`)。

**测试**:`- 去年\n  2024. 冬天很冷` → 单项;`1. 步骤一\n   - 细节\n2. 步骤二` → 「步骤二」为兄弟有序项;`1. a\n   - b\n   - c\n2. d\n3. e` 结构不变;`1. a\n   2024. 冬` → 吸收;`- a\n- b\n  3. c` → 吸收;`- a\n  1. b\n  3. c` → 结构按现状。

### P6 frontmatter cover

`frontmatter.ts:148` `extractCover`:导出并复用 parser 的 `matchImageLine` / `matchLinkedImageLine` 与 `RE_OBSIDIAN_IMAGE_LINE`(现无 wiki 整行匹配函数;`parser.ts:69` 注释提到的 `matchObsidianImageLine` 不存在,顺手修正注释),wiki 目标用 frontmatter 现有 `wikiTarget` 处理 `|`。判定顺序:
1. **wiki 优先**:值以 `![[` 或 `[[` 开头 → 整行恰为一个 wiki 链接(`/^!?\[\[([^\]]+)\]\]$/`)则取 `wikiTarget`,否则返回 null;

3. 其余 → 按原样作为路径(现状)。
**测试**:单图、带链接图、`![[a.png]]`、`[[a.png]]`、`![[a.png|300]]` → 地址;`![a](x.png) ![b](y.png)`、`![[a.png]] ![[b.png]]`、`[[a.png]] [[b.png]]` → null;畸形 `![a](x.png` → null;纯路径 `a.png` → `a.png`。
