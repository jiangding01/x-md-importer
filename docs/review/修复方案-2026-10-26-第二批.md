## 1. 阶段 A — 解析层

### P2 未闭合围栏 ⚠️ 待定

**现状**:`parser.ts` 主循环围栏分支找不到闭栏时「视为普通文本」(既有取舍),于是代码被当 Markdown 解析——`# 注释` 成 header-one 且被 `extractTitle` 抽成文章标题,`*args` 的星号被吃掉,`- x` 成列表项(与 P5 同类的「代码被改写」);能力面板也没有「围栏未闭合」提示。侧边栏预览(react-markdown,CommonMark)却把余下全文显示成代码——预览与写入不一致。

**方案 A(推荐)· 按 CommonMark:未闭合围栏一直到文末都是代码**
- 围栏分支找不到闭栏时,开栏行到文末整体产出一个 MARKDOWN 代码块(复用 `fenceMarkdown`,`closeLine = null` 补齐闭栏);`hooks.onFence` 上报该区间,标题抽取与扫描自然跳过。
- 能力面板新增 warn 项「代码围栏未闭合 · 其后全部按代码写入」,计数 1;让用户在写入前看到。
- 与 P5「引用里的代码按容器结束闭合」同一原则:代码宁可多包,不可被改写。
- 代价:正文中间误敲一个 ``` 会让其后整篇变成一个代码块——内容逐字保留、不丢,只是排版没了;面板告警提前提示。
- 例外不变:列表语境里的缩进围栏(A4)按现有容器规则;`$$` 未闭合仍回退文本(与价格写法的歧义不同)。

**方案 B · 保持回退为文本,只修标题与提示**
- 未闭合围栏仍按文本解析,但开栏行之后的标题不作文章标题;面板加同样的告警。
- 代价:代码依旧被改写(星号、`#`、`- ` 被当格式),预览与写入继续不一致。

**实施记录**:按 A 实施。check 审查补一条:开栏后一行内容都没有(文末孤立的 ```)时不产空代码块,回落文本(与 P5 同口径)。

**测试(按 A)**:审查复现(`extractTitle` 为 null、产出 1 个 MARKDOWN 块且内容逐字);未闭合围栏在文中段 → 其后内容全进代码块;围栏内的 `$$` / `>` 不解析;已有「未闭合回退为文本」的用例按新语义改写并在 PR 里逐条列出;能力面板告警计数。

### P3 HTML 注释 ⚠️ 待定

**现状**:parser 没有 HTML 块处理,`<!-- … -->` 跨多行时逐行按 Markdown 解析——注释里的 `# TODO` 成标题(并被抽成文章标题),`- 说明` 成列表项,`<!--` / `-->` 作为字面量写进 X。

**方案 A(推荐)· 注释块整体不写入**
- 块首(0-3 空格缩进)以 `<!--` 开头 → 向下找到含 `-->` 的行(可在同一行),整段跳过、不产出块(CommonMark HTML 块类型 2 的边界);找不到 `-->` → 按 CommonMark 到文末(与 P2 方案 A 同口径;若 P2 选 B,此处也改为「未闭合按文本」)。
- `hooks.onFence` 上报区间,标题抽取与扫描跳过注释内部。
- 能力面板新增 info 项「HTML 注释 · 不写入」计数,如实告知;注释后同一行还有正文(`--> 正文`)时,那段正文照常写入。
- 依据:注释是作者给自己的备注,GitHub / Obsidian / Typora 渲染时都不显示;X 不支持 HTML,写进去只会把备注原样暴露在文章里。
- 行内注释(段落中间的 `<!-- x -->`)不在本次范围,仍按字面量写入(现状)。

**实施记录**:按 A 实施,**一处偏差**:找不到 `-->` 时不按 CommonMark 吞到文末,而是回退为文本 + warn「HTML 注释未闭合」——注释块不写入,吞到文末等于整篇后文静默丢失(P2 围栏延伸到文末至少还把内容按代码写进去)。check 审查另修:未闭合计数只看普通段落,列表 / 引用里以 `<!--` 开头的正文不误计。

**方案 B · 注释作为一个文本块原样写入**:只修「被拆成标题 / 列表」,写进 X 的仍是 `<!-- … -->` 字面量。

**测试(按 A)**:审查复现(标题为「真正的标题」,正文不含注释内容);单行注释;注释后同行有正文;未闭合注释;围栏代码里的 `<!--` 不受影响;能力面板计数。

### P7 frontmatter 引号转义

**现状**:`frontmatter.ts` `stripQuotes` 只剥一层引号。`title: 'It''s fine'` → `It''s fine`;`"He said \"hi\""` → `He said \"hi\"`。

**修法**:按 YAML 1.2 解码——单引号值里 `''` → `'`;双引号值里解码 `\"` `\\` `\/` `\n` `\t` `\r` `\uXXXX` `\xXX`,未知转义保留原样(不抛错)。只作用于成对引号包裹的值;无引号值不变。`stripInlineComment` 判定闭合引号时已识别转义,两者口径一致。`cover:` 共用同一函数。

**实施记录**:check 审查补一条——解码出的控制字符(`\n`、`\x00` 等)换成空格,标题 / 封面路径都是单行值。

**测试**:三个审查复现;无引号值含反斜杠不变;未知转义 `\q` 保留;`cover: "a\"b.png"` 解码。

### P8 强调符跨进链接目标

**现状**:`findClosing`(`parser.ts`)扫闭合定界符时跳过行内代码,不跳过链接——`**注意 [链接](https://a.com/a**b) 结束**` 的闭符被 URL 里的 `**` 截走,链接丢失;`_参见 [文档](https://a.com/my_doc)_` 斜体丢失。

**修法**:扫描遇到 `[`(含 `![` 的 `[`)时调用 `matchLink(src, i)`,成立则整体跳到链接末尾。CommonMark 中链接与代码 span 的结合优先于强调。跳转结果只取决于位置,`findClosing` 的记忆化不变量不受影响(路径上每个位置结果仍相同)。`[a` 重复串下 `matchLink` 自身 O(n) 的旧问题(backlog A21)不变,不新增病态形态——用差分模糊测试与现有性能用例确认。

**实施记录**:check 审查发现跳过链接让 `[a` 重复串的病态输入比改前慢约 3 倍(`matchLink` 自身 O(n),每个 `[` 都重算)——改为在 `InlineScan` 上按起点缓存(`scan.link`),`walkInline` 与 `findClosing` 共用,实测与改前持平。

**测试**:三个审查复现(链接保留、URL 不变、外层强调包住链接);强调在链接文字内部(`[**粗**](u)`)不受影响;未闭合 `[` 照旧;新旧差分模糊对比,只允许含 `](` 的输入有差异并抽样核对。

### P9 链接 title 里的 `)`

**现状**:`matchLink` 扫链接目标时只做括号配对,`[a](https://a.com "title with ) paren")` 在 title 内的 `)` 处结束,` paren")` 漏进正文。

**修法**:目标扫描中遇到「空白后紧跟 `"` 或 `'`」→ 视为 title 起点,跳到同种引号闭合(识别 `\` 转义)再继续找 `)`;找不到闭合引号按现状处理。URL 规范化已会丢弃 title,无需改动。与 P8 同在 `matchLink`,一起做。

**测试**:审查复现(正文 `a`,url `https://a.com`);单引号 title;title 内无 `)` 的旧用例不变;URL 本身含括号(`wiki/A_(b)`)不变。

## 2. 阶段 B — 侧边栏、文案与文档

### W3 新建文章页的页面状态

**现状**:`StatusBar.tsx` 与 `PreflightCard.tsx` 以 `articleId !== null` 判断是否在文章编辑页;新建页 `articleId === null`,但 `useConnection` 判已连接、写入可用。

**修法**:两处改用 `result.isArticleEditor === true`;有 id 显示「编辑页 #id」(现状),无 id 显示新词条「新文章(尚未保存)」/ "New article (not saved yet)";不是文章路由才显示「未在文章编辑页」。

**测试**:预检行的生成逻辑抽成纯函数(`buildPreflightItems`)单测三种状态;状态条文案同理。

### W4 拖放文字

**现状**:`EditorCard.tsx` `onDragOver` / `onDrop` 无条件 `preventDefault` 并显示「拖入文件」遮罩;拖文字进来被吞掉、`readFile(undefined)` 什么也不做。

**修法**:`dataTransfer.types` 含 `'Files'` 时才 `preventDefault`、置遮罩、读文件;否则交给 textarea 原生行为(插入 / 移动文字)。判定抽成 `isFileDrag(dt)`。

**测试**:`isFileDrag` 单测;手动:从网页拖文字进编辑框、框内拖动选中文字都正常。

### W5 重探闪烁与跨窗口触发

**现状**:`useProbe` 每轮先 `setStatus('probing')` → `connected` 为 false → 「未检测到 X 文章编辑页」横幅闪现、写入按钮禁用一拍;`tabs.onActivated` 不按窗口过滤,另一个窗口切标签也会重探本窗口。

**修法**:
- 新增独立的 `loading` 状态:只有**首次**探测(尚无任何结论)显示 `probing`;之后的重探保留上次的 `status` / `result`,只置 `loading`(刷新按钮转圈),结果回来再替换。「探 A 写 B」不受影响:写入前 `startImport` 会即时重探并钉死目标(现有逻辑)。
- 挂载时 `browser.windows.getCurrent()` 记下本窗口 id;`onActivated` 只认 `windowId` 相同的事件,`onUpdated` 只认 `tab.windowId` 相同的活动标签。

**测试**:把「下一状态」计算抽成纯函数(当前状态 + 事件 → 新状态)单测;手动:写入后、切标签时横幅不再闪。

### W6 本地封面的文件夹入口

**现状**:`AssetsCard.tsx` 的 `hasLocal` 只看正文图;`startImport` 的 `usesLocalImage` 还算上本地路径的封面。

**修法**:把「本次导入是否涉及本地图」抽成纯函数 `usesLocalImage(blocks, coverSource)`,供 `AssetsCard` 与 `startImport` 共用(封面来源的判定同样共用,含 `coverKeep` / frontmatter cover 优先级),杜绝两处口径漂移。

**测试**:纯函数单测——仅正文本地图 / 仅本地封面 / 远程封面 / 关掉设置封面。

### W7 报告卡标题栏

**现状**:`ReportCard.tsx` 标题栏的绿色对勾与背景写死。

**修法**:三态——有失败(`fail > 0`)→ 危险色 + ✕;无失败但有降级或失败明细(`deg > 0` 或有 `imageFailures`,含 orphan / 错位提示)→ 警示色 + !;否则成功样式。判定与 Footer 的「是否异常」共用一个纯函数,避免两处不一致。

**测试**:纯函数单测三态;玻璃 / 暗色主题下肉眼检查对比度。

### W8 记录上限立即生效

**现状**:只在 `finishImport` 时裁剪;改设置、恢复备份后都不裁剪。

**修法**:`WorkspaceProvider` 增加 effect——`opts.histLimit` 变化(含挂载时,覆盖备份恢复后 reload 的情形)若 `historyRef.current.length` 超限,立即 `commitHistory(slice)`。多窗口同时裁剪结果相同,不会互相打架。裁剪是删除动作:设置项说明已写明「超出后自动清理最旧记录」,不再额外确认。

**测试**:裁剪计算(`pruneHistory(list, limit)`)抽纯函数单测;`'inf'` 不裁。

### W9 清除所有数据 ⚠️ 待定

**现状**:`wipeAll` 只删 4 个 `chrome.storage` key;文件夹授权 handle 在 x.com 的 IndexedDB,reload 后设置页 / 素材板挂载校准又把「已连接」写回。

**方案 A(推荐)· 尽力清除并如实提示**:wipe 前先对两级文件夹各发一次 `clearFolder`(复用现有消息,无新权限)。当前标签是 X 页时成功清除;不是 X 页时清不到(IndexedDB 只能从 x.com 页面访问)→ 继续清本地数据,并在确认文案 / 结果 toast 里说明「本地图片文件夹授权需在打开 X 页面时清除,或在素材板 / 设置中手动断开」。确认按钮文案同步补一句。

**方案 B**:只改文案,说明「清除所有数据」不包括文件夹授权。

**测试**:手动——X 页打开时清除后再进设置页显示未连接;非 X 页时出现提示。

### W11 / I3 文案进字典

- `WorkspaceProvider` 成功 toast 的 `en ? 'images' : '图片'`、`en ? 'cover' : '封面'` 改为字典词条。
- `importErrorText` 增加映射:`import already in progress`(「X 页面上已有一次写入在进行,请稍后再试」)、`draft state node not found` / `sample character: …`(「找不到可写入的编辑器,请刷新 X 页面后重试」)、`verify: only …`(已有 committed 文案族,保持);仍未知的错误保留「写入失败:<原文>」以便诊断。

**测试**:`importErrorText` 导出后单测各映射。

### I1 授权浮层多语言

**现状**:`content.ts` 浮层(标题 / 说明 / 按钮)硬编码中文。

**修法**:`connect-folder` 请求增加可选字段 `lang: 'zh' | 'en'`(sidepanel 取当前界面语言);content 侧一张 6 条文案的小字典,缺省回落中文(旧 sidepanel 兼容)。协议守卫按 `messageScope` 同样的方式归一 `lang`。

**测试**:`messageLang` 归一函数单测;手动:英文界面下连接文件夹,浮层为英文。

### D1 隐私政策

- 「按图片来源**逐个**申请」→「写入时**一次**列出本篇所有图片来源站点、由 Chrome 统一询问」(中英两版)。
- 「只读取文章中引用到的图片」→ 补充:「按文件名查找图片时,会读取所选文件夹内的目录结构(文件名),不读取其他文件的内容」。
- 生效日期不变(未发布);联系邮箱仍待用户补(既有待办)。
