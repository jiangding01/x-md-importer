## 批次一 · 上线阻断（主控亲自实现）

**B1-1 存储写失败可见化（P0-1）+ 草稿写入防抖（并入 P2-21）**
- `store.ts`：`setItem` localStorage 回退路径 rethrow（chrome 路径本就 reject）。**所有既有 `void save*` 调用点逐个兜错**：`PrefsProvider`/`SettingsProvider` 的 savePrefs/saveOptions 补 `.catch(console.error)`（低危不占 UI）；草稿/历史走下述新路径。
- 防抖器（WorkspaceProvider 内）：`schedulePersist(v)` 250ms trailing；flush 时机 = 定时到点 / 编辑器 `blur` / `visibilitychange(hidden)` / `pagehide` / 手动 `save()` / **onChanged 采纳判定前**。flush 失败 → `setStorageError(true)`，成功 → 清除。`commitHistory` 的 `saveHistory` 同样 catch → storageError。
- `save()`：await flush，成功才 toast `savedToast`，失败 toast 新词条 `errStorageWrite`。
- UI：storageError 时 DraftTab 顶部常驻错误条：「存储写入失败（可能已满）——草稿可能未保存」+「导出当前草稿」按钮（`downloadBlob` 下载 .md）。dict 新词条 zh/en。
- 单测要求：store 错误传播用例**必须** `vi.resetModules()` + 先装 chrome stub 再动态 `import('./store')`（`hasChromeStorage` 是模块加载期常量，否则只会测到 localStorage 分支的假绿）。

**B1-2 双窗口同步（P0-2）+ id 改 UUID（全局定案 1/2）**
- `draftStore.ts`/`historyStore.ts` **导出 `DRAFT_KEY`/`HISTORY_KEY`**，监听器只引用它们（禁止硬编码字符串）。
- 新增 `useEffect` 订阅 `chrome.storage.onChanged`（回调判 `areaName === 'local'`；卸载 `removeListener`；非 chrome 环境跳过）。
- 新增 `mdRef` 镜像（所有 `setMdState` 写入点同步更新）；监听器只读 ref，不读闭包 state。
- 草稿采纳策略（**写死，防实现分叉**）：
  1. `newValue === mdRef.current`（echo）→ 跳过；
  2. 有 pending 防抖写入 → **不采纳**（本地更新，随后 flush 会写回并再广播）；
  3. `importingRef.current === true` → 不采纳（导入闭包依赖 md 一致性）；
  4. `document.hasFocus()` → 不采纳（正在编辑）;
  5. 其余 → 采纳：`setMdState` 直写 + 同步 `mdRef` + 收起过期报告/预检 + toast 新词条 `draftSynced`（「草稿已从另一窗口同步」）。
- 历史采纳：以「长度 + id 序列」比对 `historyRef.current`，一致（echo）→ 跳过；否则 `setHistory` + 同步 `historyRef`。
- id：`finishImport` 改 `crypto.randomUUID()`；schema/测试/签名按全局定案 1 同步；`backup.ts` 导出 `version: 2`（定案 2）。

**B1-4 崩溃恢复屏自救出口（P1-9）**
- ErrorBoundary 内**自包含**导出实现：chrome 环境 `chrome.storage.local.get(null)`，**非 chrome 环境回退遍历 localStorage 的 `markflow:` 前缀 key**（对齐 resetAllData 的双分支）；Blob 下载。

3. `/code-review` 过当前 diff，问题修复后重跑测试。
