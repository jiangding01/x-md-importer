## 批次一 · 上线阻断（主控亲自实现）

**B1-1 存储写失败可见化（P0-1）+ 草稿写入防抖（并入 P2-21）**
- `store.ts`：`setItem` localStorage 回退路径不再吞错（rethrow）；chrome 路径保持原样（本就 reject）。
- `WorkspaceProvider`：新增 `storageError: boolean` 状态与草稿持久化防抖器：
  - `schedulePersist(v)`：400ms trailing 防抖；`flushPersist()` 在 `pagehide`/`visibilitychange(hidden)` 与手动 `save()` 时强制执行。
  - 持久化 catch → `setStorageError(true)` ；成功 → 清除。历史 `commitHistory` 的 `saveHistory` 同样 catch → storageError。
  - `save()`：`await` flush 成功后才 toast `savedToast`；失败 toast 新词条 `errStorageWrite`。
- UI：`storageError` 为 true 时 DraftTab 顶部常驻错误条（非 toast）：文案「存储写入失败（可能已满）——草稿可能未保存」+「导出当前草稿」按钮（下载 .md）。新增 dict 词条（zh/en）。
- 设置/偏好写失败仍低危：console.error 即可，不占 UI。

**B1-2 双窗口同步（P0-2）+ 历史 id 改 UUID（并入 P3）**
- `WorkspaceProvider` 挂载时订阅 `chrome.storage.onChanged`（仅 chrome 环境）：
  - 草稿 key：`newValue === 当前 md`（echo）→ 跳过；本窗口 `document.hasFocus()` → 保留本地（正在编辑，后续键入会覆盖写回）；未聚焦 → 采纳外部值（`setMdState` 直写 + 取消 pending 防抖，不经 `setMd` 以免回写风暴），并收起过期报告/预检。
  - 历史 key：以「长度 + id 序列」比对 `historyRef.current`，一致（echo）→ 跳过；否则采纳（`setHistory` + 同步 `historyRef`）。
  - 卸载时 `removeListener`。
- `finishImport` 的 HistoryItem id：`Date.now()` → `crypto.randomUUID()`（`schema.ts` 校验若断言数字需同步放宽为 string；确认 `validateHistory` 对 id 的类型口径并兼容存量数字 id）。

**B1-3 一行/小改集**
- `wxt.config.ts` permissions 加 `unlimitedStorage`（P1-8）。
- `autoReport`：`setReportVisible(opts.autoReport === 'always' || (opts.autoReport === 'anomaly' && (deg > 0 || imageFail > 0)))`（P1-10；`deg`/`imageFail` 在 `finishImport` 作用域内已有）。
- 删除 AssetsCard 封面「更换」演示按钮；`demoToast` 若再无消费一并删词条（P1-11）。
- `global.css`：删 `outline:none` 规则，新增 `:focus-visible{outline:2px solid var(--acc);outline-offset:2px}`（P1-12）。
- `writeX` ask 分支 `!fresh.connected` 提前返回补 `showToast(importErrorText('disconnected', t))`（P2-20）。

**B1-4 崩溃恢复屏加自救出口（P1-9）**
- `ErrorBoundary.tsx`：RecoveryScreen 增加「导出数据备份」按钮——**文件内自包含实现**（`chrome.storage.local.get(null)` → `Blob` 下载 JSON，不 import 任何可能已崩的模块）；「重置」按钮文案明示会清空全部数据，点击前先自动触发一次导出（失败不阻断重置，但提示）。

验收：`pnpm compile && pnpm test && pnpm build`；新增单测：store.ts 错误传播（模拟 chrome.storage reject）、历史 id 兼容校验。双窗口/防抖逻辑难以单测（依赖 chrome API + DOM 焦点），以代码 review + 逻辑推演验收，真机回归项写入 QA 文档待用户执行。

## 批次二 · 写入安全（主控亲自实现，injector 无测试覆盖，改动最小化）

**B2-1 目标 tab 钉死前移（P1-1）**
- `writeX` ask 分支：`probeXTabContent()` 前先 `resolveTargetXTab()` 拿 tabId（此分支不消耗手势；权限申请仍是 `startImport` 内手势链首个 await，不受影响），探测与弹窗都针对该 tab；tabId 存入 `pendingAskTabId` ref，`overwriteConfirm/overwriteAppend` 透传 `startImport(mode, pinnedTabId)`。
- `startImport` 增可选参 `pinnedTabId?: number`：传入则跳过内部 `resolveTargetXTab()` 直接使用（权限申请顺序不变）。非 ask 路径行为不变。
- 需确认 `probeXTabContent` 是否支持指定 tabId 探测；不支持则扩展其签名（内部本就要定位 tab）。

**B2-2 提交后失败区分（P1-3）**
- `injector.ts` `runImport`：主 `onChange` 提交成功即置 `committed = true`；所有失败返回路径（verify 不达标、images/cover 阶段异常）在结果中带 `committed`。
- `protocol.ts`：`ImportResult` 失败分支增加可选 `committed?: boolean`；`importArticle.ts` 透传。
- `WorkspaceProvider` 失败路径：`res.committed` 为 true 时改用新词条 `errFailedButCommitted`（zh：「写入未完成校验——正文可能已写入，请先检查 X 编辑器再决定是否重试」），并照常触发 `refreshProbe()`。

**B2-3 marker 清扫保文本（P2-2）**
- `sweepMarkersOnce`：命中 marker 前缀的块，剥掉 marker 串后若仍有非空文本 → 用现有替换路径改写该块文本（对齐 `replaceMarkerWithText` 非 exact 分支），仅剥后为空才删块。

**B2-4 injector 单例守卫（P2-5）**
- 模块入口：`const KEY = Symbol.for('markflow.injector.v1')`；`window[KEY]` 已存在 → 直接 return（旧实例继续服务）；否则置标记后初始化。dev 热重载语义（新代码不接管）可接受——生产首要目标是杜绝双执行。

**B2-5 小改**：`content.ts` `dataUriToFile` 加 16MB 上限（对齐远程/本地，超限走既有 failReason 降级）（P3）。

**B2-6 编辑器选择器分级（P1-2 降级后）**
- `EDITOR_SELECTOR` 拆有序数组 `[精确 Draft 容器, role=textbox, public-DraftEditor-content, 裸 contenteditable]`，逐级 `querySelectorAll`，级内仍用几何过滤；首个命中级即返回。行为对现网 DOM 等价（精确选择器本就能命中），纯稳健性。

验收：`tsc/build` 全绿；injector 无单测（既有缝隙），逐行 diff review + 真机回归项写入 QA 文档（覆盖确认弹窗期间切 tab、含 marker 字面量正文、双注入）。protocol 变更补 `protocol.test.ts` 用例。

5. 提交（批次一个 commit，信息含批次号与条目清单），push。
