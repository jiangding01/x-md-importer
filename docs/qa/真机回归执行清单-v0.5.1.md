### A1 · 写入主链路冒烟(C2 单次解析 + P11 报告按实际写入计数)
- **目的:** 写入流程改为「一次解析共享」后,标题、去 H1、封面、去首图、正文各类块、报告与记录都与改造前一致。
- **前置:** 新建空白草稿;「编辑器已有内容时」=总是覆盖;「设置文章标题」=开、「H1 处理」=移除;「设置文章封面」=开、「首图用作封面后」=从正文移除;「自动展开导入报告」=总是。
- **输入 md:**
````markdown
# A1 冒烟标题

![封面](https://pbs.twimg.com/media/HOAmor3boAAvXUp?format=jpg&name=small)

正文段落,含 **粗体** 与 [链接](https://x.com)。

- 列表一
- 列表二

```js
const a = 1;
```

| 列 A | 列 B |
|---|---|
| 1 | 2 |

![正文图](https://pbs.twimg.com/media/HOAmor3boAAvXUp?format=jpg&name=medium)
````
- **步骤:**
  1. 粘贴后先看能力面板(展开),记下各项。
  2. 点写入,等完成。
  3. 看报告卡;再到「01 界面」切换界面语言为 English,回到草稿页看报告卡;切回中文。
  4. 到「记录」页看最新一条。
- **判定:**
  - 写入前能力面板:「二级标题 → Heading」1、「粗体 / 斜体 / 删除线」1、「链接」1、「列表」2、「表格 → 原生表格」1、「代码块 → 原生代码块」1、「图片 → 上传」2。
  - X:标题框「A1 冒烟标题」;封面为第一张图;正文**不含**该 H1、**不含**第一张图;依次为段落(粗体、链接可点)、两项列表、js 代码块、2×2 原生表格、第二张图。
  - 报告卡:明细里**没有**「二级标题 → Heading」,「图片 → 上传」为 **1**(被移除的标题块与封面首图不计,P11);其余同面板;切到 English 后明细随之变英文。
  - 记录页最新一条标题「A1 冒烟标题」。
- **耗时:** 约 6 分钟

### A2 · T32-a + T32-c 空稿写入不留 `x` / 滚动到顶部(I2 / I4)

## 3. C 组:可选(2 条)

### C1 · O7 草稿保存失败后自动重试(需无 unlimitedStorage 的测试构建)
- **目的:** 此前存储写入失败后,停手就不再重试(错误条一直挂着,直到下一次键入或失焦);现在按 2s → 5s → 15s 退避自动重试,恢复后自动落盘。
- **步骤:**
  1. 按 v0.5.0 清单 C1 第 1–2 步构造测试构建并撑爆配额。
  2. 在草稿框输入一句话,等错误条出现(「存储写入失败(可能已满)——草稿可能未保存。…」)。
  3. **之后不再键入**;右键侧边栏 →「检查」,在侧边栏的 DevTools Console 执行下面的清理(执行后**不要再点回侧边栏**——点回去会触发失焦保存,就分不清是自动重试还是那次保存生效的):
```js
chrome.storage.local.get(null).then((all) => chrome.storage.local.remove(Object.keys(all).filter((k) => k.startsWith('qa_filler_'))));
```
  4. 计时观察错误条;再关掉侧边栏重新打开,看草稿内容。
  5. 删除测试构建。
- **判定:** 清理后 **15 秒内**错误条自动消失,无需再键入;重开侧边栏后草稿是第 2 步输入后的完整内容。无法构造特殊构建 → BLOCKED。
- **耗时:** 约 12 分钟

### C2 · T32-b 取样失败的撤回(I2 失败路径,只做观察)
