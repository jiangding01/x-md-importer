### A1 · T16 多图中间失败不丢原文(B1 settle)
- **目的:** 非末张图失败时,失败图 Markdown 原文保留、其余图位置正确、无 marker 残留。
- **前置:** 「编辑器已有内容时」=总是覆盖;新建空白草稿。
- **输入 md:**
```markdown
# T16 多图非末张失败

第一段文字。

![图一](https://pbs.twimg.com/media/HOAmor3boAAvXUp?format=jpg&name=small)

第二段文字。

![图二-必失败](https://pbs.twimg.com/media/MARKFLOW_NOT_EXIST_T16.jpg)

第三段文字。

![图三](https://pbs.twimg.com/media/HOAmor3boAAvXUp?format=jpg&name=medium)

结尾段落。
```
- **步骤:**
  1. 粘贴到侧边栏,点「写入 X 文章」;弹出图片域名授权时点「允许」。
  2. 等写入完成,打开导入报告。
  3. 逐段检查 X 编辑器正文。
  4. 重复 3 次(其中 1 次改用 append 模式)。
- **判定(全部满足才 PASS):**
  - 图一在「第一段文字」之后,图三在「第三段文字」之后,均上传成功,顺序正确。
  - 图二位置保留原文 `![图二-必失败](…MARKFLOW_NOT_EXIST_T16.jpg)`(或其降级文本),没丢、没跑到别处。
  - 正文无 `__MARKFLOW_IMG_` 残留;「第二段」「第三段」「结尾段落」文字完整。
  - 报告失败明细仅「图 2」一条。计数分两处:**toast** 末段为「图片 2/3」;**报告卡汇总**为「6 成功 · 0 降级 · 1 失败」(报告卡「成功」= 写入块数 − 失败图数;本例默认删 H1 后共 7 块)。
  - 3 次结果一致。
- **耗时:** 约 10 分钟

### A2 · T17 超时后晚到的 MEDIA:精确追回或如实上报,不静默错位(B2,PR #34 改写)
- **目的:** 某图超时后晚到的图片不让后图静默错位;无法归属时如实上报,**不猜归属**(已无「末轮 FIFO 按顺序分配」)。
- **前置:** 总是覆盖;空白草稿;准备 3 张远程图,第 1 张为 5~15MB 大图(如 `?format=png&name=4096x4096`),第 2、3 张普通小图;**三张图内容必须肉眼可区分**(不同 URL/图案)。X 页 DevTools→Network→节流 Slow 3G(或自定义很低上行),使第 1 张上传 >40s 但能传完。
- **输入 md:**
```markdown
# T17

段落 A

![图1大图](<大图URL>)

段落 B

![图2](<小图URL>)

段落 C

![图3](<小图URL>)
```
- **步骤:**
  1. 粘贴并点写入。
  2. **写入过程中盯着编辑器里图 1 的位置**:记录是否先出现过降级原文 `![图1大图](…)`、之后才变成图。第 1 张超时后不要取消,等整个流程结束(通道总预算 45s+3×45s)。
  3. 结束后关闭节流,检查正文与报告。
- **先判是否触发了超时路径:** injector 对「已有块、尚无 mediaId」的 pending 块「签名连续 5s 不变且块已出现 ≥20s,或出现满 32s 封顶」即判成功(`injector.ts:497-501`、`:722-726`;单图预算 40s,`:1426`),限速时图 1 **大概率并不超时**。图 1 位置若**从未出现**降级原文(直接就是图)→ 超时路径没触发,记 **BLOCKED**(不是 PASS),换更低速率/更大图重试。
- **报告明细行格式:** `图 N · 上传阶段 · <原因>`。原因文案:超时「上传超时(预算内未确认 MEDIA)」(`rsnUpTimeout`);孤儿「存在无法归位的图片(请在编辑器中手动删除)」(`rsnOrphanMedia`);错位提示「此前有图片上传超时且其结果晚到,这张及之后的图片位置可能错位,请在 X 编辑器中核对。」(`rsnMediaOrderUncertain`,**不计入失败数**)。
- **判定(触发超时路径后。核心:图 2、图 3 在各自位置,**或者**报告里有「可能错位」提示;只有「实际错位且报告无该提示」才记 FAIL):**
  - **精确追回:** 超时那刻 X 已建出图 1 的 pending 块,后来拿到 mediaId → 图 1 最终在段落 A 之后,该处降级原文已清掉;报告不再有「图 1 · 上传阶段 · 上传超时…」,toast 为「图片 3/3」。
  - **有 pending 块但收尾时仍未传完:** 报告保留「图 1 · 上传阶段 · 上传超时…」,且孤儿明细(`rsnOrphanMedia`)**必然出现**(pending 块被计入多出的图,`injector.ts:1532-1540`);但**不应**出现错位提示(其门槛是孤儿数扣除仍可追踪的超时图自身的块后仍 >0)。记录图 1 之后实际出现的位置。
  - **如实上报(无法归属):** 超时时尚无 pending 块(或块后来消失),且晚到块在收尾审计前已出现 → 报告出现「图 1 · 上传阶段 · 存在无法归位的图片(请在编辑器中手动删除)」,X Console 有 `[MarkFlow] 正文多出无法归属的图片` 警告。若其后图 2/图 3 成功归位且孤儿数扣除后仍 >0,**另有一条**错位提示(`rsnMediaOrderUncertain`),Console 有 `[MarkFlow] 超时图片的晚到结果无法追踪` 警告,按提示核对即可。**只有孤儿数 >0 才会出现错位提示**。
  - **晚于审计才到:** 图 1 在收尾之后才传完 → 报告只有「图 1 · 上传阶段 · 上传超时…」,可能既无孤儿也无错位提示(已知残留,见 `docs/review/backlog-2026-10-22.md`);正文中图 1 应是多出的一张图,图 2/图 3 仍在各自位置。记录实际现象,不记 FAIL。
  - **所有结局都必须:** 无 marker 残留(`__MARKFLOW_IMG_`);若图 2/图 3 不在各自位置(晚到的图 1 占了图 2 位置、后面依次错一位),报告必须有「可能错位」提示——没有即 FAIL。
- **耗时:** 约 15 分钟

### A4 · T19 直写与 ask 路径的权限弹窗 + 权限计数/归因(疑点 1,PR #34 补 B4/B5/B6)
- **目的:** 两条路径在新 profile 下都能弹出权限弹窗(权限申请是手势链第一个 await);拒绝有正确降级;ask 拒绝后确认不二次弹窗;toast 只计被拒 origin;内网地址不进申请。
- **前置:** 使用 0.4 的干净 profile(无任何图片域名授权)。文档含 1 张 `pbs.twimg.com` 远程图。
- **输入 md(步骤 1~5):**
```markdown
# T19

正文。

![图](https://pbs.twimg.com/media/HOAmor3boAAvXUp?format=jpg&name=small)
```
- **输入 md(步骤 6,另一图床地址自备:公网、**不带** `Access-Control-Allow-Origin`):**
```markdown
# T19-6

![图A](https://pbs.twimg.com/media/HOAmor3boAAvXUp?format=jpg&name=small)

![图B](<另一个公网图床的图片URL>)
```
- **输入 md(步骤 7):**
```markdown
# T19-7

![内网1](http://192.168.1.1/a.png)

![内网2](http://localhost:1313/a.png)

![图](https://pbs.twimg.com/media/HOAmor3boAAvXUp?format=jpg&name=small)
```
  (可选:再各加 1 张 `http://nas.lan/a.png`、`http://198.18.0.1/a.png`,验证 isBlockedHost 新增段同样不进申请。)
- **步骤:**
  1. **直写:** 「编辑器已有内容时」=总是覆盖,目标文章正文为空;点「写入 X 文章」。→ 允许。
  2. 撤销站点权限(`chrome://extensions`→本扩展详情→网站访问权限)。**ask:** 设为「每次询问」,目标文章先手动输入几个字;点写入——**先**弹 Chrome 权限弹窗(点「允许」),**之后**才弹覆盖确认弹窗,在其中选「覆盖」。
  3. 再次撤销权限,重复步骤 1,这次在 Chrome 授权弹窗点「拒绝」。
  4. **ask 拒绝后确认不二次弹窗(B6):** 撤销全部授权;「每次询问」,目标文章先手动输入几个字;点写入,Chrome 授权弹窗点「拒绝」,再在覆盖弹窗选「覆盖」;再做一轮选「追加」。
  5. **取消不收起上次报告(B6):** 先完成一次**报告卡展开**的导入(把「02 导入行为」→「自动展开导入报告」设为「总是」,或让导入含一张必失败图——默认「仅异常时」下纯净导入不展开);再点写入(「每次询问」,目标文章已有内容),在覆盖弹窗(「编辑器已有内容」)点「取消」。
  6. **一个 origin 已授权、一个被拒(B4):** 先单独导入含 `pbs.twimg.com` 图的文档并允许授权;确认另一图床域名未授权,导入上面步骤 6 的两图文档,弹窗里对未授权域名点「拒绝」。
  7. **内网地址不进申请(B5/F6):** 撤销授权,导入步骤 7 的文档。
- **判定:**
  - 步骤 1、2:点击后 Chrome 都弹出「允许访问 pbs.twimg.com」类弹窗(不是静默跳过);允许后图片正常上传。
  - 步骤 3:出现 toast「1 张远程图未获授权,可能无法下载」(`permDeniedToast`;对方图床若允许跨域,无权限也可能下载成功,故只说「可能」);正文该图若下载失败则保留原文;报告原因为「未授权该图片域名(写入时的权限申请被拒绝)」(`rsnRemotePermDenied`)。
  - 步骤 4:拒绝后出现**一次** toast;点「覆盖」/「追加」后**不再**弹 Chrome 授权弹窗,也**不再**出现第二个 toast;导入照常进行,被拒域名的图下载失败时报告原因为 `rsnRemotePermDenied`。
