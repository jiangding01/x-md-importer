### 0.9 测试环境注意事项(2026-11-04 实测踩坑)
- **pbcopy 中文乱码:** 在终端用 `pbcopy` 复制含中文的 md 会乱码(终端 / 脚本环境没有 `LANG`)。改用 `LC_ALL=en_US.UTF-8 pbcopy < 文件`,或直接从编辑器复制;粘贴后先扫一眼中文是否正常。

### R-A3 · 超时后晚到的 MEDIA:精确追回或如实上报,不静默错位(原 0.5.0 A2 / T17,B2,PR #34 改写)

### R-B20 · 回放旧快照验证自愈(fix/x-snapshot-reconcile)
- **背景:** 真机取证:X 偶发在导入收尾后 ≤1s(偶见 49s)把编辑器整体替换成更早的快照(正文 + 撤销历史一起)。快照停在「第 2 张图已插入、未归位」→ 图上方残留占位;停在「第 2 张图插入之前」→ 第 2 张图丢失、占位重现。自然复现靠运气,本用例在 Console 采集这两个旧快照并**手动回放**,主动构造两种回退。
- **自愈规则:** 导入内(结果返回前):先等 X 正文保存稳定(最多约 8 秒),再逐张核对——图在、占位在 → 把图挪回占位处并删占位(X 常把图先插在文末再挪过去,回退后图会回到文末);图不在、占位在 → 在占位处补传(每张最多一次、单次导入最多 2 张),补传后再等稳定(最多约 4 秒)复核,仍丢失则写回原文并报「图片插入后被编辑器回退丢失」;封面之后再终核一次(不补传)。终核之后还会按原图身份复查一次:此前判丢失的图若又回来了,撤销丢失记账并把图挪回占位处或顶替已写回的原文行(这条路径难以用回放构造,R-B20 未覆盖)。结果返回后(守护 60 秒):图在 → 挪回占位处并删占位;图不在 → 占位换成原文 + 告警,不补传。
- **输入 md:** 新建空文章,写入模式不限(空文章按替换),**封面关**。正文恰好两张远程图,图前后各有一段文字(便于看位置),例如:
````markdown
第一段文字。

![图一](https://<任意可访问的大尺寸 PNG 1>)

第二段文字。

![图二](https://<任意可访问的大尺寸 PNG 2>)

第三段文字。
````
- **采集脚本(导入前在 X 页面 Console 运行;只读采集,只有手动调用 `replay(...)` 时才写编辑器):**
```js
(() => {
  // 只读:每 50ms 读 Draft 节点的 props.editorState 并保存引用,不调用 onChange。
  const fiberOf = (el) => { const k = Object.keys(el).find((k) => k.startsWith('__reactFiber$')); return k ? el[k] : null; };
  const findNode = () => {
    let sn = null;
    document.querySelectorAll('[contenteditable="true"]').forEach((el) => {
      for (let f = fiberOf(el), d = 0; f && d < 80 && !sn; d++, f = f.return)
        if (f.stateNode?.props?.editorState && typeof f.stateNode.props.onChange === 'function') sn = f.stateNode;
    });
    return sn;
  };
  const M1 = /__MARKFLOW_IMG_[0-9a-z]+_1__/; // 第 2 张图(序号 1)的占位
  const mediaCount = (es) => {
    const c = es.getCurrentContent(); let n = 0;
    c.getBlockMap().forEach((b) => { const ek = b.getType() === 'atomic' ? b.getEntityAt(0) : null; if (ek && c.getEntity(ek).getType() === 'MEDIA') n++; });
    return n;
  };
  const hasM1 = (es) => es.getCurrentContent().getBlockMap().some((b) => M1.test(b.getText()));
  const saved = { pre: null, post: null };
  let last = null;
  let seenM1 = false;
  const startedAt = Date.now();
  const timer = setInterval(() => {
    // 120s 仍未采到 S_post(导入没开始 / 图没上传成功 / 占位形状变了):停止采集并告警,避免一直轮询。
    if (!saved.post && Date.now() - startedAt > 120_000) { clearInterval(timer); console.warn('[QA] 120s 内未采到 S_post,采集停止;请重新运行脚本后再导入'); return; }
    const sn = findNode(); if (!sn) return;
    const es = sn.props.editorState; if (es === last) return; last = es;
    const m = mediaCount(es);
    const m1 = hasM1(es);
    if (m1) seenM1 = true;
    if (m1 && m === 1) saved.pre = es; // S_pre:_1 占位仍在、MEDIA 数为 1 的最后状态(第 2 张插入前)
    if (m1 && m === 2) saved.post = es; // S_post:持续更新,取 MEDIA 数为 2 且 _1 仍在的最后状态(插入后、归位前)
    // _1 消失 = 第 2 张已归位:两个快照都已定格,停止采集(之后的回放不会被采进来)。
    if (seenM1 && !m1 && saved.post) { clearInterval(timer); console.log('[QA] S_pre / S_post 已采集,采集停止'); }
  }, 50);
  // 回放:把保存的旧快照经 X 自己的 onChange 写回编辑器(模拟 X 用旧快照覆盖正文)。
  window.replay = (which) => {
    const s = saved[which]; if (!s) return `未采集到 ${which}`;
    const sn = findNode(); if (!sn) return 'no editor';
    sn.props.onChange(s); return `已回放 ${which}`;
  };
  window.qaSnapshots = saved;
  return '采集已就绪:导入后 S_pre / S_post 自动保存,用 replay("pre") / replay("post") 回放';
})();
```
- **步骤(每个子用例都新建空文章、重新运行采集脚本后导入一次):**
  1. X 页面打开 DevTools Console,过滤 `MarkFlow` 与 `QA`;运行采集脚本;在 Console 输入框里**预先敲好**对应的 `replay("post")` 或 `replay("pre")`,先不回车。
  2. 点「导入到 X」,盯住正文:
     - **a(稳定窗内回放 post):** 第 2 张图跳到占位处(占位行消失)后 **1 秒内**回车执行 `replay("post")`(此时报告尚未弹出)。
     - **b(稳定窗内回放 pre):** 同 a 的时机,执行 `replay("pre")`。
     - **c(守护期回放 post):** 等报告卡弹出(结果已返回),**5 秒内**执行 `replay("post")`。
     - **d(守护期回放 pre):** 等报告卡弹出后 **5 秒内**执行 `replay("pre")`。
     - **b 追加(补传后再回放 pre):** 按 b 操作;Console 出现 `图片被编辑器回退丢失,已在原位补传` 后**立即**(报告弹出前)再执行一次 `replay("pre")`。
     - **e(首核归位后再回放 post):** 按 a 操作;Console 出现 `收尾核对:图片被编辑器回退到旧位置,已重新归位到占位处` 后**立即**(报告弹出前)再执行一次 `replay("post")`。
  3. 等报告卡弹出,再停留约 10 秒,观察正文、报告与 Console;运行 R-B18 的只读探针核对块结构。
- **判定:**
  - **a:** 报告弹出前,第 2 张图回到「第二段文字」与「第三段文字」之间(原占位处),无占位(回放的快照里图常在文末,须被挪回);Console 有 `收尾核对:图片被编辑器回退到旧位置,已重新归位到占位处`;报告「图片 2/2」、无失败明细;正文恰好 2 张图;等约 10 秒后**刷新页面**,图 2 仍在原位(确认已被 X 保存)。
  - **b:** 第 2 张图在原占位处**补回**(位于「第二段文字」与「第三段文字」之间);报告「图片 2/2」、无失败明细;Console 有 `图片被编辑器回退丢失,已在原位补传`(带 `via`);正文**恰好 2 张图**(不重复)、无占位。
  - **c:** 回放后约 1 秒内,第 2 张图回到「第二段文字」与「第三段文字」之间(原占位处),无占位;Console 有 `导入结束后图片被编辑器回退到旧位置,已重新归位到占位处`,带 `lastChangeType` / `undoDepth` / `msSinceSave`;光标不跳到文末;等约 10 秒后**刷新页面**,图 2 仍在原位、无占位。
  - **d:** 回放后约 1 秒内第 2 张图的占位被换成原文 `![图二](https://…)`(不是被删掉);Console 有 `导入结束后图片被编辑器回退丢失,已把占位符换回原文,请在正文核对并手动补图`,带诊断字段;**不会**自动补传;光标不跳到文末(回放快照自带的光标就在占位行,改写后停在该行)。报告卡不变(结果已返回,守护只告警)。
  - **b 追加:** 不发生第二次补传(Console 只有一条 `已在原位补传`);复核把第 2 张图的占位写回原文 `![图二](https://…)`;报告「图片 1/2」,失败明细第 2 张原因为「图片插入后被编辑器回退丢失(请在正文核对并手动补图)」;正文 1 张图 + 1 段原文、无占位。
  - **e:** 最终第 2 张图回到「第二段文字」与「第三段文字」之间(原占位处),无占位;报告「图片 2/2」、无失败明细;**不静默**:Console 至少两条 `已重新归位到占位处`(首核一条 + 封面后终核或残留审计一条,后者前缀为 `收尾核对:` 或 `残留审计:`);等约 10 秒后刷新页面,图 2 仍在原位。若报告弹出时图仍在文末且无第二条告警,记 FAIL。
  - 全程无报错;任一子用例回放时机错过(如回放时报告已弹出却在做 a/b)记 BLOCKED 并重做,不算 FAIL。
  - 已知限制见 R-B18「已知限制」,本用例不覆盖晚到追回图片的回退(②)。
- **耗时:** 约 25 分钟(6 个子用例)
