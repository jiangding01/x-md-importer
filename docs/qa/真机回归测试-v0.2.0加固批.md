# 真机回归测试 · v0.2.0 发布前加固批(PR #21/#22)

> **执行者**:自动化测试 Agent(Codex)+ 必要处人工辅助。
> **目标**:验证「发布前加固」批(13 项修复 + 标题 ask 弹窗)在真实 X 环境下的行为。
> **红线**:⚠️ **绝对禁止点击 X 的「Publish/发布」按钮**——本项目原则是永不自动发布,所有测试止步于草稿。测试产生的草稿文章测完可留存或手动删除。

---

## 0. 环境准备

1. 构建并加载扩展:
   ```bash
   pnpm install && pnpm build   # 项目已用 corepack 接管 pnpm,pin 11.12.0 会自动生效
   ```
   Chrome → `chrome://extensions` → 开发者模式 → 「加载已解压的扩展程序」→ 选 `.output/chrome-mv3`。
2. 登录 X 账号,打开文章编辑页:`https://x.com/compose/articles`,新建一篇草稿进入编辑器(URL 形如 `x.com/compose/articles/edit/...`)。
3. **每次重新 build 或重载扩展后,必须刷新 X 编辑页**(content script 不会自动替换,不刷新会测到旧代码——症状:三灯绿但写入报未连接)。
4. 点扩展图标打开侧边栏,确认状态条三灯(页面/编辑器/Draft 实例)全绿。
5. 打开 X 页面的 DevTools Console,保留 `[MarkFlow]` 前缀日志,供各用例断言。

**自动化能力边界(需人工辅助的点)**:
- 本地图片文件夹连接走浏览器原生 `showDirectoryPicker` 弹窗,**自动化无法驱动系统级文件选择框**——用例 T2 的「连接文件夹」步骤需人工点一次,其余断言可自动化。
- 侧边栏(chrome extension sidepanel)如果自动化框架无法直接注入,可改为静态托管 `.output/chrome-mv3/sidepanel.html` 测纯 UI 用例(T3/T4 可以,T1/T2 涉及注入必须真侧边栏)。

## T1 · 标题冲突 `ask` 询问弹窗(PR #21,核心)

前置:设置 Tab → 标题冲突策略选 **「询问」(ask)**。

### T1-a 无冲突静默设置(编辑器无标题)
1. 新建一篇空草稿(标题、正文均空)。
2. 侧边栏粘贴:
   ```markdown
   # 测试标题甲
   正文第一段。
   ```
3. 预检 → 写入 X 文章。
- **预期**:不弹任何标题弹窗;X 标题字段变为「测试标题甲」;toast 显示「标题已设置」;导入报告成功。

### T1-b 冲突 → 选「覆盖」
1. 在 X 编辑器**手动**把标题改成「原有标题乙」(正文留一行字)。
2. 侧边栏粘贴 `# 新标题丙` + 一段正文 → 写入(正文覆盖弹窗若出现选「覆盖」)。
- **预期**:正文写入后弹出 **TitleConflictDialog**,显示待写入的新标题「新标题丙」+「覆盖/保留」两按钮;点**覆盖** → X 标题变为「新标题丙」,toast「标题已设置」。

### T1-c 冲突 → 选「保留」
同 T1-b 造冲突(原标题「原有标题丁」),弹窗点**保留**。
- **预期**:X 标题**保持**「原有标题丁」不变;toast「已保留原标题」;正文正常写入,报告成功。

### T1-d 弹窗挂起期间切标签(pinnedTabId,P0 回归)
1. 开**两个** X 文章编辑页标签:文章 A(有标题,触发冲突)、文章 B(另一篇草稿)。
2. 在 A 的上下文发起导入,等 TitleConflictDialog 弹出后,**切到标签 B**,再回来点「覆盖」。
- **预期**:标题写进**文章 A**(发起导入的那篇),文章 B 的标题与正文毫发无损。这是加固批 P0——修复前会写错到 B。

### T1-e 弹窗无逃逸路径
弹窗出现时按 Esc、点遮罩空白处。
- **预期**:弹窗不消失,唯一出口是两个按钮;导入流程保持挂起,点按钮后正常收尾(不卡死、报告正常出)。

## T2 · 本地图导入后 FS handle 自动清除(B5 安全加固)

前置:准备一个含 1-2 张 PNG 的本地文件夹,md 里用相对路径引用(如 `![](assets/a.png)`)。

1. 侧边栏素材板「本篇图片文件夹」点**连接**,选中该文件夹(**人工步骤**),确认状态显示已连接(文件夹名)。
2. 粘贴含本地图的 md → 写入,等导入报告(imageOk ≥ 1)。
3. **断言 A**:导入完成后,素材板「本篇图片文件夹」与设置里的「默认文件夹」均自动变回**「未连接」**。
4. **断言 B**(暴露面验证,在 X 页 Console 执行):
   ```js
   indexedDB.databases().then(dbs => console.log(dbs.map(d => d.name)))
   ```
   导入完成后 `markflow_local_assets` 库中不应再残留可用 handle(库本身可存在,取出的 handle 应已被清除/失效)。
5. **断言 C**:紧接着再导入同一篇 md(不重新连接文件夹)。预期本地图**降级**(imageFail 计数,正文以纯文本/降级形式呈现),而不是静默用旧 handle 读出文件。

> 已知既定代价:每篇导入后都要重选文件夹,这是安全取舍,不算 bug;但如果第 3 步 UI 仍显示「已连接」而实际 handle 已清,属于**UI 撒谎,记 bug**。

## T3 · 备份恢复非法文件不砖化(B2,P0)

前置:设置 Tab → 备份「导出/恢复」。

1. **合法备份往返**:点导出,得到 JSON 文件;点恢复选该文件。预期 toast「已恢复,即将刷新面板」,面板刷新后设置/草稿/历史完好。
2. **非法文件**:构造以下文件逐个走「恢复」:
   - `a.json` 内容为 `{"foo": 1}`(结构不对)
   - `b.json` 内容为 `not json at all`(非 JSON)
   - `c.json` 内容为 `{"prefs": {"theme": 12345}, "history": "oops"}`(字段类型错)
- **预期**:每次均 toast「恢复失败:不是有效的 MarkFlow 备份」,**面板不白屏、不崩溃**,原有设置与草稿不被污染。
3. **砖化兜底**:在扩展 origin 的 DevTools 里手动写坏存储再重开侧边栏:
   ```js
   chrome.storage.local.set({ markflow_prefs: "corrupted-string" })
   ```
- **预期**:侧边栏仍能打开(ErrorBoundary 或 bootstrap 兜底,呈现可用界面或明确错误卡片),**不是白屏**。测完清理:`chrome.storage.local.remove('markflow_prefs')` 后重开恢复正常。

## T4 · 载入覆盖非空草稿确认弹窗(B3)

1. 侧边栏草稿区输入任意内容(非空)。
2. 依次触发三个入口:**载入示例**、**导入 .md 文件**、历史 Tab 里**载入**一条记录。
- **预期**:每个入口都先弹 **LoadConfirmDialog**(「覆盖当前草稿?」),点**取消** → 草稿原样;点**覆盖并载入** → 新内容替换。
3. 草稿为**空**时重复三入口。预期**不弹窗**直接载入。
4. **跨 Tab 可见性**(弹窗提升到 App 层):在**历史 Tab** 点载入触发弹窗,确认弹窗正常显示在当前视图(不是只在待发布 Tab 才可见)。

## T5 · 解析层加固抽查(parser 批)

用同一篇草稿逐段验证,写入后目测 X 正文:

| 输入 | 预期 |
|---|---|
| 文首装饰性 `---`(下方**无** frontmatter 键值,直接是正文) | 正文完整写入,**不被当 frontmatter 吞掉**;首行 `---` 呈现为分割线或按文档语义处理 |
| 真 frontmatter(`---`/`title: x`/`---`)后接正文 | frontmatter 不入正文,title 参与标题抽取 |
| 代码块内包含 `# 假标题` 和 `---` | 均按代码原文进入代码块,不被当标题/分割线 |
| `[点我](javascript:alert(1))` | 链接**不带** javascript: 跳转(降级为纯文本或剥离 URL) |
| 100+ 层嵌套强调(脚本生成 `**\*\*…**` 深嵌套) | 不崩、不卡死,正常(哪怕降级)写入 |
| 能力映射卡计数 | 与正文实际块数一致(表格/H3/删除线/推文不再虚计) |

## 结果记录格式

每个用例回报:`用例号 | PASS/FAIL | 实际现象(一句话) | 关键 Console 日志/截图`。
FAIL 的用例附:复现步骤差异、X 页 Console 报错全文、扩展侧边栏报错(右键侧边栏 → 检查)。

## 已知非 bug(勿误报)

- 导入后文件夹变「未连接」、下篇需重选 —— B5 安全加固的既定代价(缺提示 toast 是已记录的待办)。
- X 正文不支持行内代码,`` `code` `` 保留反引号纯文本是**设计行为**。
- PNG/WebP/GIF 不压缩是**设计行为**(智能保护,防截图变糊)。
- 图片 ALT 不会自动填写 —— 功能已论证不可行并搁置。
