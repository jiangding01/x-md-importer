## 1. 背景与目标

### 1.1 要做什么

Chrome 扩展（MV3）：把 Markdown 文档一键导入 **X Articles（长文）编辑器**，全格式自动排版——标题、粗体/斜体/删除线、链接、列表、引用、**代码块、表格、图片、分割线、推文嵌入**全部正确落地。不使用官方付费 API，纯浏览器层完成。交互目标：**丝滑**——拖入 .md 即预览，一键写入，全程可视进度，失败可恢复。

### 1.2 前提与边界

- 写 X Articles 需 **X Premium（$8/月）及以上**（2026-01 起下放，【官方】）。当前账号已具备权限（【实测】）。
- 入口：`x.com/compose/articles`（复数）→ Write → `x.com/compose/articles/edit/{19位draftId}`（【实测】；单数 URL 404）。
- 限制：约 100k 字符（二手）；图片经验软上限 ~25 张（xPoster 实践值）。
- **永不自动发布**；不做线程拆分；与 25k 字符「长推文」是两个功能，勿混淆。

### 1.3 竞品格局与差异化

| 工具 | 形态 | 现状 |
|---|---|---|
| **xPoster**（nevertoday，MIT） | Chrome 扩展，已上架 CWS | 唯一上架直接竞品（585 用户）；fiber 直写路线的生产验证者；7k+ 行无类型单文件 |
| punk2898/x-article-publisher | 扩展 + 本地 Node 服务 | xPoster 核心二次封装（用户当前浏览器已装同类，开发调试时注意按钮/marker 冲突） |
| wshuyi 系 Claude skills | Playwright + 系统剪贴板 | 依赖 Claude Code 环境 |
| X Article Markdown Paste（闭源 CWS） | 拦截 Ctrl+V 改写 | 宣称表格转 HiDPI 图片——**我们可以做真原生表格，直接超越** |
| MD2X / markdown-for-x | 剪贴板中转 | 手动粘贴，无注入 |

差异化定位：**注入能力对齐 xPoster + 原生表格/代码块（竞品都还在转图片）+ TypeScript 工程化 + 导入前能力预览的体验升级**。

## 2. 调研结论（事实基座）

### 2.1 编辑器技术栈 = Draft.js（三重确认）

- 【官方】X Articles API 文档明确正文格式就是 DraftJS ContentState（blocks + entities），直链 draftjs.org。
- 【实测】`.DraftEditor-root` / `.public-DraftEditor-content` 指纹全中，Lexical/ProseMirror/Slate 全部为 false。正文 contenteditable 带 `data-testid="composer"`，块 class 前缀 `longform-*`，块外层包 react-beautiful-dnd 拖拽容器。
- 【源码】xPoster 等全部基于 fiber 上的 `props.editorState`/`onChange` 工作；Twitter 维护自己的 draft-js fork。
- 含义：Draft.js 上游已归档、API 面稳定，利好直写；若 X 迁移 Lexical 需探针识别 + 降级（§7）。

### 2.2 编辑器原生格式能力（实测 + 源码）

| 格式 | 原生支持 | 表示 / 入口 |
|---|---|---|
| 标题 | ⚠️ **仅两级**：Heading=`header-one`、Subheading=`header-two`（工具栏 Body 下拉） | 粘贴白名单只认 `<h1>`/`<h2>`，`<h3>`+ 降级纯文本【实测】 |
| 粗/斜/删 | ✅ `btn-bold/italic/strikethrough` | inline style BOLD/ITALIC/STRIKETHROUGH；粘贴保留【实测】 |
| 下划线 | ❌ 无按钮，粘贴 `<u>` 被剥【实测】 | — |
| 行内代码 | ⚠️ 无按钮，粘贴 `<code>` 样式被剥【实测】 | xPoster 写 CODE inline style【源码】，渲染效果待 M0 验证 |
| 链接 | ✅ `btn-link`；粘贴 `<a>` 保留为真实 LINK entity【实测】 | `LINK` entity（MUTABLE，`{url}`） |
| 列表 | ✅ `btn-ul/ol`；粘贴保留（depth 0）【实测】 | `(un)ordered-list-item`；嵌套支持度待 M0 |
| 引用 | ✅ `btn-blockquote`；粘贴 `<blockquote>` 保留【实测】 | `blockquote` |
| **代码块** | ✅ **Insert → Code**：模态框（语言搜索 `programming-language-input` + textarea + Insert）【实测】 | atomic 块；xPoster 写 `MARKDOWN` entity（MUTABLE，`data.markdown`=完整 fence）【源码】；粘贴 `<pre><code>` 降级段落【实测】 |
| **表格** | ✅ **Insert → Table**：尺寸选择器最大 10×10，atomic 块内含真实 `<table>`【实测】🎉 | entity 形状待 M0 逆向；粘贴 `<table>` 塌缩成一行文本【实测】。⚠️ 竞品设置项暗示 `MARKDOWN` entity 或可直接渲染 Markdown 表格（M0 必验） |
| 分割线 | ✅ Insert → Divider（atomic，`role=separator`）【实测】 | `DIVIDER` entity（IMMUTABLE，`{}`）【源码】；粘贴 `<hr>` 被丢弃【实测】 |
| LaTeX | ✅ Insert → LaTeX【实测】 | 待 M0（Markdown 数学语法可作加分项） |
| 推文嵌入 | ✅ Insert → Posts | `TWEET` entity（IMMUTABLE，`{url, tweetId}`）【源码】 |
| 图片/视频/GIF | ✅ Insert → Media；**粘贴 File 实测直接触发 X 分块上传**（upload.x.com INIT/APPEND/FINALIZE）并持久化【实测】 | atomic + `MEDIA` entity（X 自动生成，含 mediaId） |
| 浮动工具条 | ❌ 选中文字无浮动工具条【实测】 | 所有格式操作走固定顶部工具栏 |

标题字段：`textarea[placeholder="Add a title"]`（React 受控，native setter + input 事件可写【源码，多方验证】）。

### 2.3 注入路线可行性（实测定稿）

| 路线 | 结论 | 证据 |
|---|---|---|
| **A. 合成 paste 事件** | ✅ **文本主路线（实测唯一可靠通道）** | 【实测】DataTransfer(text/html+text/plain) + `ClipboardEvent('paste')` dispatch 到已 focus 的 composer：defaultPrevented=true，进 EditorState，自动保存，刷新完整恢复。【源码】Draft.js `editOnPaste` 读 clipboardData 无 isTrusted 校验；React 不过滤合成事件；tweetGPT PR#16 为同类实锤 |
| **B. fiber 直写 EditorState** | ✅ 特殊块主路线（xPoster 生产验证） | 【源码】`__reactFiber$*` 上溯找 `props.editorState+onChange`；「借」页面构造器构造 ContentState；`EditorState.push(...,'insert-fragment')` + `onChange()`。atomic entity（MARKDOWN/DIVIDER/TWEET）只能走此路或 UI 自动化 |
| **C. Insert 菜单 UI 自动化** | ✅ 特殊块备选 | 【实测】代码模态框/表格尺寸按钮/Divider 菜单项 selector 均已勘明；React 受控输入用 native setter 可写 |
| **D. 剪贴板写入 + 用户 Cmd+V** | ✅ 保底 | `navigator.clipboard.write` 支持 text/html；真实可信粘贴（markdown-for-x / wshuyi 生产验证） |
| execCommand 全家 | ❌ **禁用（比预想更死）** | 【实测】insertText/insertHTML 只改 DOM 不进 Draft 状态，刷新即丢；`execCommand('delete')` 清空会把编辑器 DOM 搞坏。⚠️ 连 xPoster 的「insertText 取字符样本」技巧也不可靠，空编辑器取样改用**合成 paste 一个字符** |
| 合成 beforeinput | ❌ 完全无效 | 【实测】defaultPrevented=false 无内容进入；【源码】React 的 onBeforeInput 不监听原生 beforeinput，Draft 该通道只认纯文本 |
| chrome.debugger 可信按键 | ❌ 不采用 | 必弹「正在调试」横幅 + 敏感权限 |

**粘贴通道 HTML 白名单（实测映射）**：`<h1>/<h2>`✅ `<h3>+`→纯文本 · `<strong>/<em>/<del>`✅ `<u>/<code>`样式剥除 · `<a>`✅ · `<ul>/<ol>/<blockquote>`✅ · `<pre>/<table>/<hr>`❌（降级/塌缩/丢弃）→ **生成回退 HTML 时必须以此白名单为上限**。

### 2.4 图片上传机制（双路线均验证）

- **主**：合成 paste 携带 File【实测直接可用】或 fiber 找 X 的 `onFilesAdded` prop 直调【xPoster 生产验证】。后者可配合 `EditorState.forceSelection` 光标钉位实现精确落位；前者简单但落位在当前光标。M0 对比后定主备。
- 上传完成检测：diff blockMap 新增 atomic MEDIA entity → 递归提取 mediaId（键名穷举防御）→ 搬运归位到 marker → 清 marker（xPoster 全套机制可搬运）。
- 远程图片：**background service worker** 抓取（content script 受 CORS 限制），optional host permission 按 origin 运行时申请；`chrome.runtime.sendMessage` 仅 JSON → 图片转 base64/ArrayBuffer 传递；跨 world `window.postMessage` 可直接传 File（结构化克隆）。
- 本地图片：File System Access API 选文件夹，handle 持久化 IndexedDB，路径安全器防 `..` 逃逸（xPoster 模式）。
- 预压缩：长边 ≤1280、JPEG q82、>150KB 才压（上传更快、更抗限流）。

### 2.5 标题与封面

- 标题：native value setter + input/change 事件（多方验证）；GraphQL `ArticleEntityUpdateTitle` 作可选增强。
- 封面：常驻 `fileInput`（accept jpeg/png/webp）直接 setFiles；GraphQL `ArticleEntityUpdateCoverMedia` 可选。
- ⚠️ GraphQL queryId 硬编码脆弱且属 X 私有 web API → **v1 默认仅 UI 通道，GraphQL 做成默认关闭的设置项**（待拍板 §11.1）。

### 2.6 实机勘察记录

- 账号可用 Articles；草稿即时自动保存（只有进 Draft 状态的内容才被保存——「防脏数据」的天然屏障）。
- 草稿删除：列表行 More → Delete Article → confirmationSheetConfirm。
- 截图存档（scratchpad）：`01-articles-home` ~ `07-selection-no-floating-toolbar`。
- 站点经验已沉淀：`~/.claude/skills/web-access/references/site-patterns/x.com-articles.md`。

## 3. 总体架构（MV3）

```
┌──────────────────────────────────────────────────────────────┐
│ Side Panel (React + TS)                                       │
│ 草稿工作台 · 能力映射预览 · 导入进度 · 记录 · 设置             │
└──────────────┬───────────────────────────────────────────────┘
               │ chrome.runtime / chrome.tabs 消息（JSON）
┌──────────────▼───────────────────────────────────────────────┐
│ Content Script — ISOLATED world（x.com）                      │
│ 路由/编辑器检测 · preflight · Markdown 解析 · 导入计划编排     │
│ 图片准备（background 代理 / FS Access / dataURI）              │
│ 页面内入口 UI（Shadow DOM：导入按钮 / 拖放 / 进度浮层）        │
└──────────────┬───────────────────────────────────────────────┘
               │ window.postMessage（结构化克隆 + nonce 校验，可传 File）
┌──────────────▼───────────────────────────────────────────────┐
│ Injector — MAIN world content script（manifest 声明式注入）    │
│ fiber 定位 Draft 实例 · 合成 paste · atomic 直写 · marker 事务 │
│ onFilesAdded 上传桥 · Insert 菜单自动化 · 探针诊断             │
└──────────────────────────────────────────────────────────────┘
┌──────────────────────────────────────────────────────────────┐
│ Background Service Worker                                     │
│ 远程图片代理（SSRF 防御/重试/LRU 缓存）· optional 权限 · 面板  │
└──────────────────────────────────────────────────────────────┘
```

- 两 world 通信：`window.postMessage` + 随机 nonce + `event.source === window` 校验；只传数据不传能力。
- UI 挂 Shadow DOM（open），防 X 清理带重挂机制。
- 权限：`storage, sidePanel, tabs`，零静态 host_permissions，远程图按 origin 运行时申请（商店审核友好，xPoster 模式）。

## 4. 核心管线：Markdown → X 编辑器

```
.md → ①remark+remark-gfm 解析(mdast) → ②IR + 能力映射（预览/降级提示）
→ ③PastePlan { htmlChunks, atomicOps, imageOps, markerPrefix }
→ ④preflight 探针 → ⑤注入执行（marker 事务）：
    标题 → 正文（合成 paste，特殊块占位 __XMD_{nonce}_{TYPE}_{n}__）
    → atomic 替换（代码/表格/分割线/推文：fiber 直写 entity，失败→UI 自动化，再失败→图片/文本降级）
    → 图片逐张（光标钉位 → 上传 → MEDIA diff → 归位 → 清 marker）
    → 封面（可选） → 多轮 marker 清理至收敛（catch 分支也执行）
→ ⑥逐项导入报告（成功/降级/失败，失败项保留原文兜底）
```

### 4.1 解析层

- **remark + remark-gfm + remark-frontmatter**：产出目标是结构化 blocks，AST 映射最精准；GFM 表格/删除线开箱即用。
- 标题优先级：frontmatter > 首个 H1（取出不进正文）> 文件名；封面：frontmatter `cover` > 首图（可配）。
- 回退 HTML 按 §2.3 白名单生成，DOMPurify 净化。

### 4.2 格式映射矩阵（最终版）

| Markdown | 落地 | 降级链 |
|---|---|---|
| `#` | 文章标题字段 | — |
| `##` | `header-one`（Heading） | — |
| `###` | `header-two`（Subheading） | — |
| `####`+ | **粗体段落**（默认，可配为 Subheading） | — |
| `**` `*` `~~` | BOLD / ITALIC / STRIKETHROUGH | — |
| `` ` `` 行内代码 | CODE inline style（fiber 写入，渲染待 M0） | 等宽 Unicode 或保留反引号（可配） |
| `[t](url)` | LINK entity | — |
| 列表 | list-item（嵌套 depth 待 M0，不支持则扁平化+缩进符） | — |
| 任务列表 `- [ ]` | ☑/☐ 符号列表（可配普通列表） | — |
| GFM 脚注 | 文末「注释」编号列表（可配忽略） | — |
| 内嵌 HTML 块 | 剥标签保留文本（可配忽略） | — |
| `>` 引用 | `blockquote`（多行合并） | — |
| ` ``` ` 代码块 | **MARKDOWN entity（X 原生代码块，带语言）** | ①Insert 菜单自动化 ②Shiki 渲 PNG ③blockquote |
| GFM 表格 | **原生表格 entity（M0 逆向 shape；或经 MARKDOWN entity 渲染，M0 验证）** | ①Insert 菜单自动化+逐格填充 ②canvas 渲 PNG（xPoster 验证）③制表文本 |
| `---` | DIVIDER entity | Insert 菜单自动化 → 省略+提示 |
| `![](…)` | File 粘贴/onFilesAdded → MEDIA；**alt 自动写入 X 图注（caption）** | 保留 `![alt](src)` 原文 + 警告 |
| `![[图片]]`（Obsidian） | 同上（本地文件夹解析） | 同上 |
| 推文 URL 独行 | TWEET entity | 普通链接 |
| `$…$` 数学（可选 M4+） | LaTeX 块 | 代码块 |

**核心原则：任何失败不静默丢内容**——降级为原始 Markdown 文本 + 报告明示。

### 4.3 注入引擎分层（探针驱动）

- **L1 组合拳（默认）**：正文文本走**合成 paste**（实测最稳），特殊块走 **fiber 直写 atomic entity**（唯一全自动全格式路线）；空编辑器字符样本用「粘贴单字符」替代 execCommand。
- **L2 UI 自动化**：fiber 探针失败时，特殊块回退为模拟 Insert 菜单（selector 已勘明）。
- **L3 剪贴板 + 引导 Cmd+V**：合成 paste 也失效时的保底；特殊块降级图片/文本。
- 改进 xPoster：**selection 定位的 fragment 增量插入**（不整篇覆盖 blockMap），支持追加与断点续导。

## 6. 交互原则（丝滑体验的底线）

1. **零等待感**：解析与能力映射在输入时即时完成；写入阶段每 ≤1s 必有进度变化；图片并发准备、串行注入。
2. **可预期**：写入前用户已经从能力映射面板知道每一项会变成什么；不会出现「导入完才发现表格丢了」。
3. **可撤离**：任何阶段可取消，取消后编辑器零残留（marker 事务保证）；覆盖前必确认。
4. **可恢复**：失败项保留原文可复制；图片可单张重试；记录可整篇重导。
5. **不越权**：永不触碰发布按钮；权限按需申请并说明用途。

## 7. 健壮性与风险

| 风险 | 应对 |
|---|---|
| X 改版（选择器/fiber/entity 变化） | preflight 探针（editor/DraftNode/onFilesAdded/entity 试写）+ 多级选择器 fallback + 自动降级 L2/L3 + 诊断快照导出 |
| X 迁移 Lexical | 探针识别 `data-lexical-editor` → 合成 paste 对 Lexical 依然有效（其官方 e2e 即此法），特殊块降级 |
| 上传异步竞态（key 变化/marker 回弹） | 多轮清理收敛 + entityKey/mediaId 兜底定位 + pending 稳定性判定（xPoster 全套） |
| 已装同类扩展冲突（用户浏览器现有 punk2898 版） | 启动检测同类按钮/marker 前缀，提示禁用；自身 marker 带独特 nonce |
| 风控 | 不模拟键盘连发；节奏仅为 React 提交等待；图片限速；真实登录态 |
| 大文档性能 | 分块 paste；CharacterList 数组一次性构建；订阅 onChange 代替轮询 |
| XSS | 主链路不经 HTML；回退 HTML 过 DOMPurify |

## 8. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript（函数式模块，无 class） | 用户偏好 + 跨界消息需类型化 |
| 扩展框架 | **WXT** | 最活跃 MV3 框架，多 world content script、Shadow DOM UI、HMR 原生支持 |
| UI | React 18 + TS | 用户主力栈 |
| Markdown | remark + remark-gfm + remark-frontmatter | AST→blocks 映射最精准 |
| 净化 | DOMPurify（仅回退 HTML 路径） | 事实标准 |
| 表格降级渲染 | 离屏 canvas 自绘（零依赖，xPoster 验证） | 仅作原生表格失败的兜底 |
| 代码块降级渲染 | Shiki（可选，M3） | 最流行高亮器 |
| 包管理 | pnpm | 用户偏好 |

## 9. 里程碑

- **M0 探针 PoC（先行，半天~1 天）**：在真实编辑器验证并冻结注入层假设——
  ① fiber 定位 + 借构造器写一个 unstyled 块；② 粘贴取字符样本；③ 逐一试写 MARKDOWN/DIVIDER/TWEET entity 确认渲染；④ **用 Insert 菜单手工造原生表格/代码块/LaTeX，dump contentState 逆向 entity shape**；⑤ **验证 MARKDOWN entity 是否渲染完整 Markdown（含表格）**——竞品设置项暗示可行，若成立表格导入将大幅简化；⑥ File 粘贴 vs onFilesAdded 上传对比；⑦ CODE inline style 渲染验证；⑧ 嵌套列表 depth 渲染验证；⑨ **图注写入路径**（图片块 "Provide a caption" 输入的 selector / entity data 字段，决定 alt→caption 的实现层）；⑩ 标题字段已有内容时 native setter 覆盖行为（决定标题冲突策略实现）。
- **M1 文本全格式**：标题 + 正文（标题级别/粗斜删/链接/列表/引用）+ preflight + 进度 UI + 覆盖确认 + 基础报告，端到端。
- **M2 图片管线**：本地/远程/dataURI + 归位 + 封面 + 素材区 UI。
- **M3 特殊块**：代码块/表格/分割线/推文嵌入（原生 entity 主路线 + 三级降级链 + 策略设置）。
- **M4 体验打磨**：能力映射面板、拖放导入、批量队列、记录、智能标点、成功反馈、诊断面板。
